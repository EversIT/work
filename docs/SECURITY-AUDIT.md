# Security audit of the upstream codebase (NestJS + Vue)

Scope: `packages/backend` (NestJS 10 / TypeORM / Fastify), `packages/frontend` (Vue 3),
Docker/nginx/compose files. Method: manual source review. Nothing from the upstream
project was executed. Findings are tied to the file they were observed in, so they can be
re-verified. Severity follows a plain impact × exploitability judgement.

The rewrite does **not** port these behaviours. The right-hand column states the design rule
the new code follows.

## Critical

| #   | Finding                                                                                                                                                                                                                                                                                                                                                               | Where                                                             | Rewrite rule                                                                                                                                                                               |
| --- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| C1  | **Privilege escalation via mass assignment.** `UpdateUserDto extends PartialType(User)`, so `PUT /users/:id` accepts `roles`, `project`, `password` from the body. Any user can make themselves `admin`.                                                                                                                                                              | `users/dto/update.user.dto.ts`, `users.controller.ts`             | Request DTOs list allowed fields explicitly. Roles are never client-writable.                                                                                                              |
| C2  | **Passwords stored in plaintext on update.** `UsersService.update` merges the DTO without hashing, so a changed password is saved raw and then fails `bcrypt.compare` (account lockout) or is set to an attacker-chosen hash string.                                                                                                                                  | `users.service.ts`                                                | Separate change-password endpoint, requires the current password, Argon2id.                                                                                                                |
| C3  | **SQL injection in activity listing.** `orderBy(\`cardActivity.${sortBy}\`)` interpolates a query-string value into SQL.                                                                                                                                                                                                                                              | `card.activities.service.ts`                                      | Sort columns come from a closed enum mapped to static SQL. All values are bound parameters (SQLx).                                                                                         |
| C4  | **Broken object-level authorization (IDOR) on many endpoints.** No ownership or tenant check for: filters, watchers, card activities, card lists, notifications (update), project-users (all), `GET /projects/invite/:code`, automation validation (also unauthenticated), mailer. Any logged-in user can read or modify other tenants' data by guessing integer ids. | the controllers listed; `*service.ts` contain no `authorize` call | Every handler resolves the resource's project through the DB and checks membership and role in one place (`authz` module). Handlers cannot reach data without an `AuthContext`.            |
| C5  | **Arbitrary file write via upload name.** The stored path is `join("uploads", "<timestamp>-" + originalname)`; `originalname` is attacker-controlled and `../` segments escape the directory.                                                                                                                                                                         | `local.storage.adapter.ts`, `files.service.ts`                    | Storage key is a server-generated UUID. Client file name is metadata only, never a path.                                                                                                   |
| C6  | **Unauthenticated file download and stored XSS.** `GET /files/:id` has no guard and no tenant check. The stored client MIME type is trusted, and no `Content-Disposition` or `nosniff` is set, so uploaded HTML/SVG can run script on the app origin.                                                                                                                 | `files.controller.ts`                                             | Auth required. Content type sniffed server-side from an allow-list. `nosniff`, `Content-Disposition: attachment` unless the type is a safe image, and a restrictive CSP on file responses. |
| C7  | **Cross-tenant realtime data leak.** Socket handler `room:join` lets any authenticated socket join any room name, including another user's id (rooms are keyed by user id), so notifications can be eavesdropped. CORS is `*`.                                                                                                                                        | `sockets/socket.gateway.ts`                                       | Rooms are derived server-side from verified membership. Client room names are not accepted. Origin allow-list.                                                                             |
| C8  | **Weak or default secrets shipped.** `.env.example` sets the JWT secret set to the project name and DB password `12345678`; Grafana defaults to `admin/admin`. The JWT secret signs every session.                                                                                                                                                                    | `.env.example`, `docker-compose.yml`                              | No default for any secret. The server refuses to start if the JWT key is shorter than 32 bytes. Compose uses `${VAR:?}`.                                                                   |

| #   | Finding                                                                                                                                                                                                                                                                                                                          | Where                                                            | Rewrite rule                                                                                                                                          |
| --- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| H1  | **Invite flow grants `admin`.** `registerWithInvite` creates every invited user with role `admin`. The invite code is static, never expires, and `GET /projects/invite/:code` is public and returns the whole project row. The `:inviteCode` path param of `POST /auth/invite/:inviteCode` is ignored in favour of a body field. | `auth.service.ts`, `projects.controller.ts`                      | Invites are rows with role, expiry, max uses, stored hashed. Default role is `member`.                                                                |
| H2  | **`checkPermission` with id arrays passes if any one id matches** (`findOne` + `In(...)`). Callers that pass arrays authorize the whole set on one hit.                                                                                                                                                                          | `access.control.service.ts`                                      | Check is all-or-nothing.                                                                                                                              |
| H3  | **Unauthenticated Bull Board and Swagger.** `/bullmq` exposes queue contents (email bodies, job payloads) and allows retry and delete. `/docs` is public.                                                                                                                                                                        | `main.ts`                                                        | No queue dashboard. API docs only when explicitly enabled.                                                                                            |
| H4  | **OAuth `state` is unsigned base64 containing `userId`.** The callback is unauthenticated, so an attacker can bind their own Slack workspace to a victim's account (login-CSRF style) or forge the user. Slack tokens are stored in plaintext JSON.                                                                              | `slack.integration.service.ts`, `user.integration.controller.ts` | Random one-time state bound to the session, stored server-side with a TTL. Tokens encrypted at rest (AES-256-GCM, key from env).                      |
| H5  | **Authentication hardening absent.** No rate limiting or lockout on `/auth/login` or `/auth/register`. User enumeration through `EMAIL_EXISTS`. Login uses `ILIKE` on the email, so `%` and `_` act as wildcards (`%@corp.com` matches the first such user).                                                                     | `auth.service.ts`, `users.service.ts`                            | Per-IP and per-account throttling, generic errors, case-insensitive exact match on a normalized email column.                                         |
| H6  | **JWT design.** 7-day bearer token, no revocation, no refresh, embeds the full user object (PII) in the token. The roles inside the token are trusted by the guard.                                                                                                                                                              | `auth.module.ts`, `jwt.strategy.ts`                              | 15-minute access token plus rotating refresh token (hashed in the DB, revocable). Token carries only `sub`, `sid`, `exp`. Roles are read from the DB. |
| H7  | **Mailer abuse and HTML injection.** `POST /mailer/mention` lets any user send mail to any user id with an attacker-chosen `route` link and unescaped names inside the HTML body (phishing from the product's own sender).                                                                                                       | `mailer.controller.ts`, `mailer.service.ts`                      | No public mail endpoint. Mail is only sent from server-side events. Templates escape all values and links are built from the configured frontend URL. |
| H8  | **Query filter engine exposes arbitrary column names.** `FieldFilter.field` passes only a charset regex, so any column reachable by the query (including joined tables) can be filtered with `LIKE`, which gives a blind oracle. The jsonb values are built by string concatenation (`["${value}"]`).                            | `query.builder.helper.ts`                                        | Filters compile against a per-entity allow-list of columns. jsonb keys are bound parameters.                                                          |
| H9  | **TLS verification disabled** for the database when SSL is on (`rejectUnauthorized: false`).                                                                                                                                                                                                                                     | `config/typeorm.ts`                                              | Verification on by default, an explicit CA setting for private CAs.                                                                                   |

## Low / hygiene

- Verbose request-body logging option (`ENABLE_REQ_BODY_LOGGING`) can write passwords to logs. The rewrite redacts by construction.
- `bcrypt` with default cost, no pepper, no password policy. The rewrite uses Argon2id with an OWASP-level parameter set and a minimum length check.
- `Math.random()` used for query parameter naming. Harmless, but the rewrite uses none of this.
- `JSON.parse` of untrusted `state` without try/catch (500 instead of 400).

## Attack surface that did not exist upstream, and how it is protected

The rewrite adds features a Jira alternative needs. Each one is a new way to attack the system, so each has
its own tests (`apps/backend/src/e2e*.rs`, `apps/frontend-e2e`).

| Feature | Risk | Protection | Test |
|---------|------|------------|------|
| **API tokens** (`wrk_...`, Bearer or Jira-style Basic `email:token`) | A leaked token is a long-lived credential. | Only a SHA-256 is stored; the secret is shown once. Scope `read` (safe methods only) or `write`; optional expiry; instant revocation; per-token rate limit. Tokens act with the owner's permissions, never more. Managing tokens, changing the password, deleting the account and linking integrations need a real session, so a leaked token cannot mint tokens or lock the owner out. Basic auth must name the token's owner. | `api_tokens_work_like_jira_tokens_and_cannot_escalate`, `api-tokens.spec.ts` |
| **Incoming webhooks** (`POST /hooks/{id}/{secret}`) | Unauthenticated endpoint. | 256-bit secret in the URL, stored hashed, compared in constant time; shown once; rotation kills the old URL. Unknown id, wrong secret, disabled and deleted automations are indistinguishable (404). Body limit 64 KB, per-IP and per-automation rate limit. A `card_id` in the body must belong to the automation's workspace. Runs execute with the automation owner's rights and stop if they lost access. | `incoming_webhooks_trigger_automations`, `webhooks.spec.ts` |
| **Outgoing webhooks** (automation action) | **SSRF**: an admin could make the server call internal services or cloud metadata. | https only (http opt-in), no credentials in URLs, destination resolved and *every* address checked against loopback/private/link-local/CGNAT/multicast/documentation ranges (incl. IPv4-mapped and NAT64 IPv6), connection pinned to the checked address (no DNS rebinding), redirects not followed, 10 s timeout. The URL itself is never templated. Payloads are signed (`X-Work-Signature`, HMAC-SHA256, key derived from the server secret, readable by admins only). Creating automations needs project admin rights. | `ssrf.rs` unit tests, `outgoing_webhooks_cannot_reach_internal_addresses`, `outgoing_webhooks_are_signed` |
| **Automation e-mail** | Spam relay / phishing from the product's own sender. | Recipients must be project members (operator can opt in to external addresses); bodies are escaped; 20 mails per automation and hour. | `automations_send_mail_only_to_project_members` |
| **Password reset** | Account takeover, user enumeration. | Same answer for known and unknown addresses; 3 mails per address and hour; random single-use token stored hashed, 60-minute expiry, redeemed atomically; all sessions revoked afterwards. | `password_reset_by_email`, `mail.spec.ts` |
| **Invitations by e-mail** | Link forwarded to someone else. | The invite is bound to the invited address: only an account with that e-mail can redeem it; single use; expiring. | `invite_by_email_is_bound_to_the_address` |
| **Realtime (SSE)** | Reading other users' events. | The stream is bound to the user id in the verified token; clients cannot choose or join channels. `no-transform` keeps proxies from buffering it. | `hub` unit test, `collab.spec.ts` |
| **File uploads / downloads** | Stored XSS, path traversal, quota bypass. | Server-chosen storage keys, magic-byte sniffing with an allow-list (no HTML/SVG/executables), `nosniff`, `attachment` unless a safe image, sandbox CSP, authenticated and project-scoped, quota enforced under an advisory lock. | `files_are_sniffed_scoped_and_served_safely` |
| **Filter engine** | SQL injection through user-defined filters and sorts. | Closed AST, allow-listed targets, typed comparisons, bound parameters only; depth/size limits. | `filters.rs` unit tests, `filters_sorting_and_pagination_are_safe_and_correct` |
| **OAuth (Slack)** | Login CSRF, token theft. | One-time server-side `state` bound to the user's session; tokens encrypted at rest (AES-256-GCM, bound to the user). | `integrations.rs` unit tests |

## Not verified

- Dependency vulnerabilities (`npm audit`) were not run, because nothing from the upstream tree was installed or executed.
- The original frontend's TipTap rendering path was not traced to the end. The rewrite does not use TipTap: descriptions and comments are plain text rendered through React (always escaped).
- The original automation handlers were read for behaviour only. The rewrite re-implements them with owner-rights checks, a depth limit against loops and non-evaluating placeholders (see the table above).

## Known residual risks of the rewrite

- Registration reveals whether an e-mail exists (`409`); closing it properly needs e-mail verification at sign-up.
- No MFA, no account lock-out after repeated failures beyond rate limiting.
- The CSP allows `'unsafe-inline'` scripts (Next bootstrap). A per-request nonce is the next step.
- The in-process rate limiter is per instance; run a shared limiter in front when scaling out.
- Dependency audits (`cargo audit`, `npm audit`) run in CI; results depend on the advisory database at that time.
